Process Documentation: all_property_management scraper
======================================================

Date: 2026-02-01

Issue: Node.js fetch() DNS resolution failure
-------------------------------------------------

Symptom:
  - Scraper failed with: "TypeError: fetch failed"
  - Cause: "getaddrinfo EAI_AGAIN api.allpropertymanagement.com"
  - This is a DNS resolution error specific to Node.js in this environment

Debugging steps:

1. Verified main website is accessible:
   curl -s -o /dev/null -w "%{http_code}" https://www.allpropertymanagement.com/
   Result: 200 (success)

2. Tested API endpoint directly with curl:
   curl -s "https://api.allpropertymanagement.com/public/v1/propertyManagers" -H "Accept: application/json"
   Result: Success - returned 2,737 property manager records

3. Conclusion: Node's built-in fetch has DNS issues in this environment, but curl works fine

Solution:
---------
Replaced async fetchWithRetry() using Node fetch with synchronous fetchWithCurl()
using child_process.execSync to shell out to curl.

Changes made to scraper.ts:
- Added: import { execSync } from 'child_process'
- Replaced: fetchWithRetry<T>(url, retries) -> fetchWithCurl<T>(url, retries)
- Converted async functions to sync since curl is blocking
- Simplified scrapeAllManagers() to sequential processing

Result:
-------
- Full scrape completed successfully
- 2,737 property managers scraped
- 0 errors
- Rate: ~6 records/second
- Total time: ~7 minutes
